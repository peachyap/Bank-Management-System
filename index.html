How it is built

Two classes with a clear split. BankAccount protects one customer's data. BankManagement holds the collection and finds accounts. main() handles input and output.

functionmain()

Creates one BankManagement object, shows the menu, reads the choice and calls the matching method. Repeats until the user answers anything other than y.

How a deposit travels through the code

Withdraw follows the same path. The only extra step is the balance check inside withdraw().

  1. Choose option 4main() reads the choice and the switch enters case 4.
  2. Find the accountbank.findAccount(num) scans the vector and returns a pointer to the match.
  3. Check the pointerIf it is not NULL the program asks for an amount. Otherwise it prints Account Not Found.
  4. Update in placeaccount->deposit(amount) changes the stored object, not a copy.

What I would improve

Reviewing my own submission, these are the gaps I found and how I would close them.

findAccount() can end without returning

Now
If no account matches, the loop finishes and the function reaches its closing brace with no return. That is undefined behaviour in C++, and main() then trusts the result in its NULL check.
Fix
Add return nullptr; after the loop.

Search is silent on a miss

Now
searchAccount() prints its heading and nothing else when the number does not exist.
Fix
Track whether a match was found and print Account Not Found.
Try it with fixes on

Amounts and numbers go unchecked

Now
A negative deposit lowers the balance, a negative withdrawal raises it, and two accounts can share a number.
Fix
Reject amounts of zero or less, and check the number is unused in AddAccount().
Try it with fixes on

Names stop at the first space

Now
cin >> name reads one word, so a full name is cut short and the rest spills into the next prompt.
Fix
Read the name with getline() after clearing the input buffer.
Try it with fixes on

Accounts vanish on exit

Now
Everything lives in a vector in memory, so closing the program loses every account.
Fix
Save to a file with fstream on exit and load it on start.
Choose Exit in the demo

No way to delete an account

Now
The menu has no remove option, so an account created by mistake stays until the program closes.
Fix
Add a removeAccount() method that erases the matching entry from the vector.
Try it with fixes on

Windows-only clear, odd exit code

Now
system("cls") only works on Windows, and exit(1) reports an error status for a normal quit.
Fix
Clear the screen portably and finish with return 0.
